# Character and Leveling Outline

Implementation outline for the Character and Leveling system.

## Part 1: Overview

The character system works as follows (with one character and two support artifacts active during each game):

A character selected from a list of existing characters, each with special unique abilities activated by pressing a new hotkey (configured in settings, default f). These are called "active" abilities.
Each character also has abilities which affect gameplay without the need of a button press (ex: increasing score from certain moves). These are called "passive" abilities.
Unlocked characters don't have levels - their active and passive abilities will be equal for all players.
The active abilities will have a "meter" that fills during gameplay. When the meter is full, the player can activate the ability by pressing the hotkey. The meter will fill based on both the score gain of the team (everyone has an individual meter, but score gains from each player will fill everyone's meter simultaneously) as well as slowly over time. Each character will have different fill rates for both these categories (say, a 1.5x fill rate on score and a 100/sec meter that requires 5,000 to activate).

Two support artifacts from the player's artifact inventory. These artifacts will be acquired through various means (discussed later) and each have various "effects". The artifact list contains each of the 7 tetromino pieces by default, and more artifacts that are non-tetromino will be added later. The effects of an artifact are not fixed by type (i.e. any artifact can have a "score more on spin" or "score more on non-spin" effect), but each artifact will roll their type's effect table during acquisition to determine its specific effect and quality (a z-piece artifact, for instance, could have a 70% chance of effect A with quality 20 and 30% chance of effect B with quality 25, while other artifacts may have their own chances).

Acquired artifacts will have "levels". Each level of an artifact corresponds to an additional effect - at level 1, the artifact has one effect; at level 2, the artifacts have two effects. When an artifact is generated by code, it will roll the effect and quality for each level independently. The same effect can be rolled multiple times - for example, a z-piece artifact at level 3 could roll effect A twice at varying qualities, and effect B once. These effects will be tracked separately on the artifact as different entries in the array storing them. If an artifact is leveled up directly (one-to-one, not through fusion), it will keep its previous effects but roll the effect table for each additional level. An artifact cannot be leveled down.

## Part 2: Artifact Acquisition

When a game is finished, UltraStack currently stores the player's xp into the database. XP gain is calculated based on gamemode-specific formulae. The initial artifact acquisition system will build off the xp system - a function will run on each game victory (only victories) for modes that grant xp. An artifact will be rolled, with a fixed level 1, of a random type out of the 7 tetromino pieces (only these pieces, even as more artifacts are added). The artifact will have a hidden "base quality" randomly generated based on the xp gain - more xp means a higher base quality. Base quality is bounded from 0-100. Then, the artifact will roll its effects based on its type using the fixed effect probability tables. The effect probability tables provide an effect and quality. Based on the "base quality" of the artifact, the quality of the entry from the table will be randomly tweaked - a number from 0-100 will be rolled and checked to be smaller than the base quality, multiplying the quality by 0.9 if fail and 1.1 if succeed (thus, a higher base quality is better). This 0-100 roll will be performed 5 times in total, meaning the theoretical output quality of that effect can be as low as around 59% of the default or as high as 161%.

With acquired artifacts, players can also choose to perform artifact "fusion". Players will select 5 artifacts of the same level from their inventory, and they will be destroyed to create one artifact (important that these artifacts must all be of the same level). Each of the five artifacts' base quality will be randomly multiplied by 0.8 and 2.0 with a 50% chance of each, and the average of these five values will be the new artifact's base value. This base value can theoretically exceed 100 (i.e. if all of the artifacts being fused are already close to 100 base value), so this is an expected outcome. If the base value is above 100, randomize the base value to be any value between 40-80, and set the level 1 higher. This is the intended method for players to acquire artifacts above level 1 - by performing fusion on artifacts until they level up, and repeating. The output of fusion should always be the same level as the five input artifacts - you cannot downgrade, so fusing 5 level 2 artifacts grants either a level 2 or 3 as a result. Additionally, the output of fusion should have a 20% chance to be the type of each of its parts - so fusing 5 of the same piece type guarantees a result of that piece type, but 3 of type A and 2 of type B results in a 60%/40% chance for the fused piece to be that type.

There will be more ways to level up or reroll artifacts in the future, but these are the only two planned methods of obtaining artifacts for now.

## Part 3: Artifact Gameplay and Effects

Defined effects for each artifact in gameplay, where `q` represents the quality of that specific effect:
a. All line clears with this piece score `1.0*q` percent more
b. All spins with this piece score `2.0*q` percent more
c. All line clears with this piece fill players' meters `1.5*q` percent more
d. All spins with this piece fill players' meters `3.0*q` percent more
e. While this artifact is equipped, any line clear fills your meter `0.25*q` percent more
f. While this artifact is equipped, any spin fills your meter `0.5*q` percent more
g. (currently unobtainable) While this artifact is equipped, passive time-based meter fill speed is increased by `2.0*q`

Notes:
* These formulas will be display-rounded to the nearest tenth (so "12.7%" instead of "12.759%") but in-game effects will be accurate to the actual formula.
* More effects will be implemented later, keep the system robust.

Defined tables for each artifact type and the effects they provide (based on lettering from the effects list). Formatted as "percentage to get effect | effect letter(s) from above list | [base quality q]":
* I piece artifact: (20% a,c [q=8], 10% b,d [q=15], 20% e,f [q=10])
* T piece artifact: (15% a,b,c,d [q=8], 20% e,f [q=10])
* O piece artifact: (45% a,c [q=18], 5% e,f [q=20])
* S/Z/L/J piece artifacts: (10% a,c [q=14], 20% b,d [q=16], 20% e,f [q=10])

Notes:
* In the future, artifacts that are not piece-based will be added. They will have effects similar to e, f, and g, where the effect is not piece-specific.
* Artifacts will use the textures in assets/char_img/artifacts. There are already .png files for each piece.

## Part 4: Character Gameplay

The system will have two starting characters. Players will have a list of unlocked characters (true/false for each character) stored in database, and these two characters (id 0 and 1) will be marked as true upon account creation.

Character 1: (Placeholder Name) 3-Mino

Active Ability: Swaps the current piece with a I3 or L3 (50% chance of each).
Meter: 1.0x score, 100/sec, 3,000 required for ability

Passive Ability: All line clears with I3 and L3 will score 50% more and fill other players' meters by 4x, filling own meter by 1x.

Character 2: (Placeholder Name) Wizard

Active Ability: Replaces the current piece with an I.
Meter: 0.5x score, 300/sec, 2,000 required for ability

Passive Ability: Queue will contain only J, L, S, T, Z pieces. (Note: program a new queue alongsize 7-bag and 3mino, name it wizard-bag).

Note: Characters and their meters will display in-game on the right side of the board. The meter will be drawn as a partial donut, where the percentage to max fill is represented by how much the donut is to making it a full 360 degrees (rather than a standard bar graph). The character will be drawn in front of the donut such that the donut has the same radius as the character's drawn image width. The donut's color is based on the player's ripple circle color (red, green, etc). There is a background donut to the bar that will be a darker version of that color, and always filling the whole 360 degrees.

Note 2: Both characters will use the assets/char_img/placeholder_character.png texture for now, although they will use different textures later.

## Part 5: Usable Modes

The characters will not be usable in existing Score and Puzzle gamemodes. However, artifacts can still be earned from these gamemodes.

From now on, the gamemode prefix MULTIPLAYER_ implies no character and artifact usage for scoring, while CHARACTER_ implies that gamemode supports character usage. Add a CHARACTER_SCORE mode which has the same mechanics as MULTIPLAYER_SCORE but with characters and artifacts enabled (don't add a CHARACTER_PUZZLE mode).

In the multiplayer room listing and both the LAN and multiplayer room lobbies, players can see a character sidebar on the left. This sidebar displays their currently selected character and artifacts. Players can click on this sidebar, entering their character system and artifact menu screen to select character and artifacts.
* If the multiplayer room is in a gamemode where characters are unusable, the sidebar will be displayed desaturated in grayscale. Clicking into the sidebar will bring the player into the character system screen, but it will stay desaturated unless the room changes to a gamemode that supports the system. There will also be a text warning at the bottom of the character system screen that reads, "The Character System is not available for this gamemode and selected effects will not be active".
* If the player is in LAN, they will have every character unlocked by default and two pre-generated artifacts in their selection, although they will not be able to gain any more artifacts or use the fusion system.
* If the game starts at any time while the player is in the character system screen, the player will be immediately pulled out of it into the game.

The screen layout is as follows:
* Character selection on the top half - a big display of the character in the middle top, and a sidebar on the right of each unlocked/locked character (locked characters are in grayscale). Unlocked characters can be clicked which selects them.
* Artifact selection on the bottom half:
    * A big grid inventory, similar to Minecraft, of each artifact on the bottom right.
    * The two selected artifacts in two disconnected grid boxes on the top right.
    * A "swap out" button between them. Normally gray and inactive, activates when the user highlights a selected artifact. If both a selected artifact and inventory artifact are highlighted, it swaps the inventory artifact into the selected position, and the selected artifact back into the inventory. If only a selected artifact is highlighted, it moves it back into the inventory, leaving a blank spot (users can leave it like this for no-artifact challenge runs).
    * On the left, a display of the stats of the highlighted selected artifact on the top (if any, otherwise leave blank with the text "Select an artifact"), and a display of the stats of the highlighted inventory artifact on the bottom (if any, otherwise leave blank with same text).
    * The player can click an artifact to highlight it. Only one artifact from the top and one from the bottom can be highlighted at any time.
* Fusion button at the very bottom center - if clicked, brings user to Artifact Fusion screen. This screen just has the inventory (player can't fuse currently selected artifacts) at the bottom left, and five Fusion slots above on the top left, with an "add to fusion" and "remove from fusion" button in between. The bottom right displays the stats of the currently highlighted artifact in the inventory. When the "add to fusion" button is clicked, the artifact stays in the inventory but the grid tile is given a transparent red overlay. The first empty Fusion slot fills with the icon of the artifact as well. If the highlighted artifact is in a fusion slot, the "remove from fusion" button will allow the user to remove the artifact from fusion. On the top right, a single result slot and "perform fusion" button await. Pressing the button will delete the fusion artifacts from the inventory and create a new artifact in the inventory, displaying it in the result slot, and highlighting it automatically. The artifact will stay in the result slot until the next item is fused, or if it is selected for fusion itself.
    * Note: Since all 6 of the fusion slots (the 5 input slots and one output slot) are just holding links to the inventory slot of the actual item, they aren't actually treated as a "storage" the same way the selected artifact list is. Rather, they just display which items are going to be used in fusion / recently outputted from fusion by holding a reference to that inventory item. The user should still be able to highlight that artifact by clicking on the fusion slot, however, for better ease of use.
